Chapter 1: Web Architecture & FastAPI Fundamentals

Jab bhi hum koi modern web application (jaise Amazon, Flipkart, ya hamara Oranza Catalog) banate hain, to uske do main hisse hote hain:

  • Frontend (Client): Jo user ko browser me screen par dikhta hai (React, HTML, CSS). Iska kaam sundar buttons, forms aur cards render karna hai.
  • Backend (Server): Jo server par chalta hai (Python + FastAPI). Iska kaam business logic execute karna, security check karna, aur database me data save/fetch karna hai.

API kya hoti hai? (Beginner Analogy)

API (Application Programming Interface) ek Restaurant ke Waiter ki tarah hoti hai:

Client (Customer): Menu dekh kar waiter ko order deta hai ➔ HTTP Request
API (Waiter): Order ko kitchen (Database/Backend) tak le jata hai.
Backend (Kitchen): Khana (Data) prepare karta hai.
API (Waiter): Tayyar khana customer ki table par wapas le aata hai ➔ HTTP Response (JSON).

Security Guard (auth.py -> JWT Token verify karta hai) ▼ [ Pydantic Validation ] (schemas.py -> Request payload validate karta hai) │ │ 3. Controller/Service (crud.py -> Business logic execute karta hai) ▼ [ SQLAlchemy ORM ] (Python code ko SQL queries me convert karta hai) │ │ 4. SELECT * FROM products WHERE title LIKE '%chair%'; ▼ [ SQLite Database ] (catalog.db file on disk) │ │ 5. Raw SQL rows return karta hai ▼ [ Pydantic Serialization ] (schemas.ProductResponse -> Clean JSON formatting) │ │ 6. HTTP 200 OK + JSON Response ▼ [ React Frontend ] (Screen par Product Cards render karta hai!)

Chapter 2: Project Directory Structure & Core Files

Hamare backend ka code clean modular architecture par structured hai:

File Name Primary Responsibility Beginner Explanation
database.py DB Connection & Engine Database file (catalog.db) ka connection banata hai aur session provide karta hai.
models.py SQLAlchemy ORM Tables Database ki actual tables (Users, Products, Categories, Settings) define karta hai.
schemas.py Pydantic Data Schemas API me aane wale aur jane wale JSON data ka data-type aur validation check karta hai.
crud.py Database Operations Actual SQL queries (Create, Read, Update, Delete) perform karne wale Python functions.
auth.py Security & JWT Tokens Bcrypt password hashing aur JWT Bearer token generation/verification handle karta hai.
main.py FastAPI Endpoints Entrypoint Saare URLs/routes ko register karta hai, CORS handle karta hai aur server run karta hai.

models.py vs schemas.py ka Difference (Sabse Bada Beginner Confusion)

models.py (SQL Database Table): Ye database engine ko batata hai ki disk par hard drive me table kaise banegi (Columns: Integer, String, Primary Key, Foreign Key).

schemas.py (Pydantic Validator): Ye network layer par client se aane wale JSON ko check karta hai (Jaise: email valid format me hai ya nahi, password kam se kam 6 characters ka hai ya nahi).

Chapter 3: Database Connection & Session Management (database.py)

Database se connect karne ke liye hum SQLAlchemy ORM ka use karte hain. ORM ka full form hai Object Relational Mapper. Iska fayda ye hai ki hume manually complex SQL queries nahi likhni padti, balki Python classes aur objects ke zariye database handle hota hai!

database.py Code:

from sqlalchemy import create_engine
from sqlalchemy.orm import declarative_base, sessionmaker

# 1. Local SQLite file path
SQLALCHEMY_DATABASE_URL = "sqlite:///./catalog.db"

# 2. Database Engine create karna
engine = create_engine(
    SQLALCHEMY_DATABASE_URL, 
    connect_args={"check_same_thread": False} # SQLite threading fix
)

# 3. SessionLocal: Har request ke liye DB session factory
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

# 4. Declarative Base class jisse hamare saare models inherit karenge
Base = declarative_base()

# 5. Dependency Injection: get_db()
def get_db():
    db = SessionLocal()
    try:
        yield db   # Route ko DB session hand-over karta hai
    finally:
        db.close() # Request poori hote hi session safely close ho jata hai
Key Learning (Dependency Injection - get_db): yield keyword ka use karke FastAPI request aane par darwaza (session) kholta hai aur request complete hone par finally me darwaza band kar deta hai. Isse connection leak nahi hota!

Chapter 4: Authentication, Hashing & JWT Security (auth.py)

Frontend Connection:

Connects to LoginPage.jsx aur RegisterPage.jsx.

Real Problem:

Database me users ka password plain text (e.g. password123) me save karna dangerous hai! Agar database leak ho gaya to saare accounts hack ho jayenge. Iske alawa, HTTP stateless hota hai, isliye har request par server ko user ki identity verify karni hoti hai.

Solution (Bcrypt + JWT):

  1. Bcrypt Hashing: One-way cryptographic hash jo password ko random encrypted string bana deta hai jise decrypt nahi kiya ja sakta.
  2. JWT (JSON Web Token): Login hone par user ko ek digital identity pass milta hai: eyJhbGciOi...
[ Client (React) ] [ FastAPI Backend ] │ │ │ 1. POST /login {email, password} │ ├────────────────────────────────────>│ 2. Check user in DB │ │ 3. verify_password(raw, hashed) │ │ 4. create_access_token(user.email, role) │ 5. { access_token: "eyJ..." } │ │<────────────────────────────────────┤ │ │ │ 6. Protected Call (Bearer Token) │ │ GET /api/v1/auth/me │ │ Header: Authorization: Bearer eyJ│ ├────────────────────────────────────>│ 7. decode_access_token() │ │ 8. Role guard check (seller/admin) │ 9. Returns user profile details │ │<────────────────────────────────────┤

Code Example (Role Guards):

def require_seller_or_admin(current_user = Depends(get_current_user)):
    # Only Sellers or Admins can access
    if current_user.role not in ["seller", "admin"]:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Access forbidden: Requires Seller or Admin privileges"
        )
    return current_user

def get_products(db: Session, category_id=None, search=None, is_featured=None, skip=0, limit=50):
    query = db.query(models.Product)
    
    # 1. Category Filter
    if category_id:
        query = query.filter(models.Product.category_id == category_id)
        
    # 2. Case-Insensitive Multi-field Search
    if search:
        search_fmt = f"%{search.strip()}%"
        query = query.filter(
            or_(
                models.Product.title.ilike(search_fmt),
                models.Product.short_description.ilike(search_fmt),
                models.Product.sku.ilike(search_fmt)
            )
        )
        
    # 3. Featured Products Filter
    if is_featured is not None:
        query = query.filter(models.Product.is_featured == is_featured)
        
    # 4. Pagination (skip & limit)
    return query.offset(skip).limit(limit).all()

8. File & Image Upload System (POST /api/v1/uploads/image)

Frontend Section: AddProductPage.jsx me computer se product photos upload karna.

Logic & Implementation Steps:

  1. File Extension Check: Sirf valid images (.jpg, .png, .webp) allow honi chahiye.
  2. Collision-Safe Unique Filename: Agar do users photo.jpg upload karenge to pehli photo overwrite na ho, iske liye hum uuid.uuid4().hex[:8] attach karte hain: img_a1b2c3d4_sofa.jpg.
  3. Disk Streaming: Binary data ko static/uploads/images/ folder me save karte hain.
  4. Live HTTP URL Generation: Client ko direct public link return hota hai: http://127.0.0.1:8000/static/uploads/images/img_a1b2c3d4_sofa.jpg.
# main.py me static folder mount karna
app.mount("/static", StaticFiles(directory=STATIC_DIR), name="static")

@app.post("/api/v1/uploads/image")
async def upload_product_image(request: Request, file: UploadFile = File(...)):
    ext = os.path.splitext(file.filename)[1].lower()
    if ext not in {".jpg", ".jpeg", ".png", ".webp"}:
        raise HTTPException(status_code=400, detail="Invalid image format")
        
    unique_name = f"img_{uuid.uuid4().hex[:8]}_{file.filename}"
    save_path = os.path.join(UPLOADS_IMAGES_DIR, unique_name)
    
    with open(save_path, "wb") as buffer:
        shutil.copyfileobj(file.file, buffer)
        
    base_url = str(request.base_url).rstrip("/")
    return {
        "status": "success",
        "url": f"{base_url}/static/uploads/images/{unique_name}"
    }

12. Excel / CSV Data Export Engine (GET /api/v1/contact/export/csv)

Frontend Section: Dashboard me Export Leads to Excel button.

Architecture: StreamingResponse with BOM

import csv
import io
from fastapi.responses import StreamingResponse

@app.get("/api/v1/contact/export/csv")
def export_leads_csv(db: Session = Depends(get_db), current_user = Depends(auth.require_seller_or_admin)):
    leads = db.query(models.ContactMessage).order_by(models.ContactMessage.id.desc()).all()
    
    # 1. Virtual in-memory string file (No disk write)
    output = io.StringIO()
    output.write('\ufeff') # UTF-8 BOM: Microsoft Excel compatibility fix
    writer = csv.writer(output)
    
    # 2. Write CSV Header & Rows
    writer.writerow(["ID", "Date", "Customer Name", "Phone", "Category", "Message"])
    for l in leads:
        writer.writerow([l.id, l.created_at, l.name, l.phone, l.category, l.message])
        
    filename = "oranza_leads.csv"
    return StreamingResponse(
        iter([output.getvalue()]),
        media_type="text/csv; charset=utf-8",
        headers={"Content-Disposition": f"attachment; filename={filename}"}
    )

Chapter 13: Fresher Cheat Sheet & Common Errors

Issue / Error Why it happens? How to Fix?
422 Unprocessable Entity Pydantic validation fail ho gaya (e.g. integer field me string bhej di, ya required field miss kar di). Response body me detail[0].loc check karo aur required payload verify karo.
401 Unauthorized Request ke header me Authorization: Bearer <token> nahi bheja ya token expire ho gaya. Pehle /auth/login karke fresh token lo aur headers me pass karo.
403 Forbidden User logged in hai lekin uske paas required role (e.g. admin) nahi hai. Admin user account se login karo (admin@oranza.com).
CORS Error in React Browser ne security ke liye port 3001 se port 8000 ki request block kar di. FastAPI me CORSMiddleware lagao with allow_origins=["*"].
UnicodeEncodeError in Windows Windows terminal cp1252 use karta hai aur special symbol (jaise ₹ ya emoji) print karne par crash hota hai. Console prints me emojis avoid karein ya UTF-8 safe encode/decode karein.
